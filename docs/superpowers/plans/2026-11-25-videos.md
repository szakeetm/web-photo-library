# Videos and Live Photos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Index, show and play videos (1080p HEVC previews made by ffmpeg on first open or by a pausable "Convert all"), and play Live Photo motion clips in the viewer.

**Architecture:** Videos become assets with `kind = 'video'`; Live Photo motion clips become `motion` rows attached to their still. A new `VideoConversions` service (PhotoCore, separate from `JobRunner`) runs one ffmpeg process at a time with an on-demand priority lane. The HTTP layer gains byte-range serving for originals, previews and motion clips; the web viewer gains a video player and a press-and-hold Live Photo overlay.

**Tech Stack:** Swift 6 (Hummingbird 2, GRDB, AVFoundation, ImageIO), ffmpeg 9 from Homebrew (`hevc_videotoolbox`, `libvpx-vp9` decoder), SvelteKit + vitest.

**Spec:** `docs/superpowers/specs/2026-11-25-videos-design.md`

## Global Constraints

- The library folder is never written to.
- Previews: HEVC via `hevc_videotoolbox`, `-b:v 4M`, short side scaled to 1080 only when larger, `-tag:v hvc1`, AAC 128k, `-movflags +faststart`, `-map_metadata -1`, written to a temp file then renamed to `<cacheDir>/video/<id[0:2]>/<id>.mp4`.
- HLG sources keep HDR: `-profile:v main10 -pix_fmt p010le -color_primaries bt2020 -color_trc arib-std-b67 -colorspace bt2020nc`.
- `servePlan = "original"` iff codec ∈ {h264, hevc} AND extension ∈ {mov, mp4, m4v} AND min(width, height) ≤ 1080; else `"preview"`.
- ffmpeg is looked up at `/opt/homebrew/bin/ffmpeg`, `/usr/local/bin/ffmpeg`, then each `PATH` entry (`ffprobe` next to it).
- Video extensions: `mov mp4 m4v 3gp avi mkv webm`.
- Motion clips: always served as the original when codec ∈ {h264, hevc}; never converted otherwise unless opened.
- Nothing under `/api/assets/*/video`, `/api/assets/*/motion`, `/api/assets/*/original` is ever stored by the service worker, the image cache or Download.
- `apiVersion`, `CLIENT_API_VERSION`, `catalogFormat`, `CATALOG_FORMAT` all go from 4 to 5.
- Server tests: `scripts/test-server.sh`; web tests: `cd web && npm test`. Tests that need ffmpeg use `.enabled(if: FFmpeg.locate() != nil)`.

## Review Focus

1. A still appears in a later scan with the same basename (or content id) as a video already indexed as an asset → that video becomes the still's motion clip and its asset disappears from the timeline. (Task 3 test `videoBecomesMotionWhenStillAppears`.)
2. Two people (or a phone and a desktop) open the same unconverted video at once → one ffmpeg process, both see the same progress. (Task 5 test `concurrentRequestsShareOneConversion`.)
3. Safari's range forms: `bytes=0-1` probe, open-ended `bytes=100-`, suffix `bytes=-500`, and a start past EOF → correct 206 bodies and a 416 for the last. (Task 6 test `rangeForms`.)
4. A portrait iPhone video (rotation in `preferredTransform`) → catalog width < height, and the preview scales its short side (width) to 1080. (Task 1 test `rotatedVideoReportsDisplaySize`, Task 5 test `argumentsUseDisplaySize`.)
5. ffmpeg missing → a 4K HEVC video still plays its original, a VP9 video answers "unplayable", Settings says ffmpeg is missing. (Task 6 test `noFFmpegFallbacks`.)

### Task 3: Scanner indexes videos and attaches motion clips

**Files:**
- Modify: `server/Sources/PhotoCore/Indexing/LibraryScanner.swift`, `server/Sources/PhotoCore/Indexing/MetadataResolver.swift`, `server/Sources/PhotoCore/Jobs/JobRunner.swift` (summary text)

**Interfaces:**
- Consumes: Task 1 `VideoProbe`, `ProbeResult.contentId`; Task 2 records.
- Produces:
  - `LibraryScanner.videoExtensions: Set<String>`; `ScanReport.liveMotion: Int` (motion clips attached), and the summary line "N Live Photo videos attached" replacing videos in "videos/other files skipped".
  - `MetadataResolver.resolve(video: VideoProbeResult, sidecar: SidecarData?, fileMTime: Date, serverTZ: TimeZone) -> ResolvedMetadata` (same precedence: sidecar → embedded → mtime).
  - `CatalogService.motionURL(id: String) throws -> URL?` (validated like `sourceURL`: size + mtime match).

Algorithm (per root, in `detectChanges`):
1. `walk` returns images and videos separately. Index images first (unchanged logic, plus `contentId` and `probeVersion = currentProbeVersion` written by `applyMetadata`). Images whose asset has `probeVersion < currentProbeVersion` are re-probed (metadata only, no rehash) even when size/mtime are unchanged.
2. For each video file: it is **motion** if a still exists in the same directory with the same basename (case-insensitive, extension ignored) or if its `contentId` equals some present asset's `contentId` (`kind = 'photo'`). Motion → upsert `motion` keyed by that still's asset id (first found wins for Takeout duplicates), record `ChangeLog` upsert for the still; if the video path had a `file` row (previously a video asset), delete it and `markMissingIfOrphaned`. Unchanged motion rows (same size/mtime) are skipped without probing.
3. Otherwise index as a video asset through `indexCandidate` (hash, sidecar, `kind = "video"`, `duration`, `videoCodec`, `videoHDR`, `servePlan` from `VideoProbe.servePlan`, width/height, make/model; no camera exposure fields).
4. Motion rows whose file disappeared are deleted (change log upsert for the still).
`reindex` re-probes videos via `VideoProbe` and refreshes motion rows the same way.

### Task 5: Conversion service

**Files:**
- Create: `server/Sources/PhotoCore/Video/VideoConversions.swift`
- Modify: `server/Sources/PhotoAPI/Services.swift` (own one instance), `server/Sources/PhotoCore/Jobs/JobRunner.swift` (purge and rebuild-caches hooks via closures passed in)

**Interfaces:**
- Consumes: `FFmpeg`, `Asset` video columns, `CatalogService.sourceURL`, `CatalogService.motionURL`.
- Produces:
  ```swift
  public enum VideoStatus: Equatable, Sendable, Codable {
      case ready                 // preview exists, or servePlan == original
      case converting(Double)    // 0...1
      case queued
      case failed(String)
      case unavailable           // ffmpeg missing
  }
  public struct ConvertAllState: Codable, Sendable, Equatable {
      public var state: String   // "idle" | "running" | "paused"
      public var done: Int; public var total: Int
      public var current: String?; public var progress: Double?
      public var needed: Int     // videos with servePlan == preview and no preview
      public var converted: Int; public var bytes: Int64
      public var ffmpeg: Bool
  }
  public final class VideoConversions: @unchecked Sendable {
      public init(db: AppDatabase, catalog: CatalogService, cacheDir: URL, ffmpeg: URL?)
      public func previewURL(id: String) -> URL
      public func motionPreviewURL(id: String) -> URL          // <cacheDir>/video/<id[0:2]>/<id>.motion.mp4
      public func status(id: String) -> VideoStatus
      @discardableResult public func request(id: String, motion: Bool = false) -> VideoStatus   // jumps the queue
      public func startAll(); public func pause(); public func allState() -> ConvertAllState
      public func remove(id: String); public func clear() throws
      static func arguments(source: URL, output: URL, width: Int, height: Int, hdr: Bool) -> [String]
  }
  ```
- Behaviour: one worker thread; queue = on-demand ids (FIFO, ahead) then "Convert all" ids (newest first). A request for an id already queued/running returns its status. `pause()` kills the running ffmpeg only if it belongs to "Convert all" (an on-demand conversion finishes), deletes its temp file, empties the "Convert all" list, state `paused`. `startAll()` rebuilds the list from assets needing a preview. State is memory only (restart → `idle`). Progress parsed from `-progress pipe:1` `out_time_us` ÷ duration. Exit ≠ 0 → `asset.videoError` set, status `failed`; success clears `videoError`. `request` on a failed id returns `.failed` without retrying; `startAll()` includes failed ids (that is the retry), and a re-index clears `videoError`.
